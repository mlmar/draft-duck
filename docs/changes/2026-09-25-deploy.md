# Deploy

## Intent of the changes

Put the v1 draft helper on the public internet: static client on GitHub Pages at `/draft-duck/`, Fastify in a Cloud Run image. Yahoo, auth, live NBA, and AI stay the later live-season half.

Review follow-up on the same branch: stop the merge job from dying on a read-only GHA cache, stop Pages from shipping without `404.html`, and keep local listen on loopback. Locks live in [deploy.md](../deploy.md) (Do not regress), `verify-deploy.yml`, and the client path/URL tests.

## What did not change

- Ranker formulas, `POST /rank` body, `dd.draftProfile`, quiz order, or board chrome.
- No accounts, no Start server functions for ranking, no ADP, no taken list.

## Tradeoffs

- **Cloud Run process, not Vercel Functions.** The API already loads the CSV once at boot. A container keeps that model. Vercel would have needed a serverless rewrite.
- **Pages project path.** Vite `base` and the router `basepath` come from `PUBLIC_BASE_PATH`. Local stays `/`.
- **Deploy by git SHA.** Cloud Run pins a digest at deploy time. `:latest` is only a pointer. Image cleanup is a later Artifact Registry policy, not an Action.
- **Push to main, not `pull_request` closed.** Closed-PR runs cannot write the GHA cache. `cache-to: type=gha` would fail before Cloud Run updates.

## High-level overview of the current implementation

The API prefers Cloud Run's `PORT`. Local listen is `127.0.0.1`. The image sets `HOST=0.0.0.0`. `tsx` is a production dependency so the image can `npm ci --omit=dev`. Image install is `--ignore-scripts`, drop Vite, then tsx's `esbuild/install.js`. `npm rebuild esbuild` walks Vite's 0.25 copy and dies. A root Dockerfile copies api, core, and the season CSV.

PRs run `verify-deploy` (tests, Pages client build, `404.html` in the publish dir, Docker build no push). Push to `main` or dispatch runs the two deploy jobs. The API job authenticates with WIF, pushes `draft-duck-api:$GITHUB_SHA`, and points Cloud Run at that tag with `--max-instances=3`. The client job checks `PUBLIC_API_URL`, bakes `/draft-duck/`, copies `dist/client/_shell.html` to `dist/client/404.html` only, and peaceiris publishes `build/client`.

## Surfaces touched

- Fastify listen / CORS origin (still one origin).
- Client fetch error copy. Router and Vite base path.
- Workflows `verify-deploy`, `deploy-api`, and `deploy-client`.
- Docs: roadmap, deploy runbook, review plan.

## User-visible vs contract

- **UI:** Production lives under `/draft-duck/`. Rank errors no longer say to start the local API.
- **Local:** `npm run dev:api` is loopback again.
- **Contract:** `POST /rank` unchanged. `PUBLIC_API_URL` is bake-time. `CLIENT_ORIGIN` must be `https://mlmar.github.io` in Cloud Run.

## Known gaps

- First client deploy needs `PUBLIC_API_URL` set after Cloud Run exists.
- Pages must be pointed at `build/client` once that branch exists.
- Artifact Registry cleanup policies are not applied yet.
- WIF and the Artifact Registry repo are console work, not created by the repo.
- 512Mi Cloud Run memory is a first guess. Bump to 1Gi only if boot OOM.

## How to verify

1. `npm run dev:api` binds `127.0.0.1:3300`. Quiz still lands on `/draft` at localhost.
2. `npm test` passes core and the client path/URL cases.
3. `PUBLIC_BASE_PATH=/draft-duck/ PUBLIC_API_URL=https://example-run.app npm run build -w @draft-duck/client`. `app/client/dist/client/404.html` exists.
4. On the PR, Verify deploy is green.
5. After merge or dispatch: `GET {origin}/health` is ok. Console shows max instances 3.
6. Set `PUBLIC_API_URL`. Dispatch Deploy client. Open `/draft-duck/`, finish the quiz, cold-open `/draft-duck/draft`.
