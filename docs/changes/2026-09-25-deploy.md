# Deploy

## Intent of the changes

Put the v1 draft helper on the public internet: static client on GitHub Pages at `/draft-duck/`, Fastify in a Cloud Run image. Yahoo, auth, live NBA, and AI stay the later live-season half.

## What did not change

- Ranker formulas, `POST /rank` body, `dd.draftProfile`, quiz order, or board chrome.
- No accounts, no Start server functions for ranking, no ADP, no taken list.

## Tradeoffs

- **Cloud Run process, not Vercel Functions.** The API already loads the CSV once at boot. A container keeps that model. Vercel would have needed a serverless rewrite.
- **Pages project path.** Vite `base` and the router `basepath` come from `PUBLIC_BASE_PATH`. Local stays `/`.
- **Deploy by git SHA.** Cloud Run pins a digest at deploy time. `:latest` is only a pointer. Image cleanup is a later Artifact Registry policy, not an Action.

## High-level overview of the current implementation

The API listens on `0.0.0.0` and prefers Cloud Run's `PORT`. `tsx` is a production dependency so the image can `npm ci --omit=dev`. A root Dockerfile copies api, core, and the season CSV.

Two Actions: merge to `main` or manual dispatch. The API job authenticates with WIF, pushes `draft-duck-api:$GITHUB_SHA`, and points Cloud Run at that tag. The client job bakes `PUBLIC_API_URL` and `/draft-duck/`, copies the Start `_shell.html` to `404.html`, and peaceiris publishes `build/client`.

## Surfaces touched

- Fastify listen / CORS origin (still one origin).
- Client fetch error copy. Router and Vite base path.
- Workflows `deploy-api` and `deploy-client`.
- Docs: roadmap, deploy runbook.

## User-visible vs contract

- **UI:** Production lives under `/draft-duck/`. Rank errors no longer say to start the local API.
- **Contract:** `POST /rank` unchanged. `PUBLIC_API_URL` is bake-time. `CLIENT_ORIGIN` must be `https://mlmar.github.io` in Cloud Run.

## Known gaps

- First client deploy needs `PUBLIC_API_URL` set after Cloud Run exists.
- Pages must be pointed at `build/client` once that branch exists.
- Artifact Registry cleanup policies are not applied yet.
- WIF and the Artifact Registry repo are console work, not created by the repo.

## How to verify

1. `npm run dev:api` and `npm run dev:client`. Quiz still lands on `/draft` at localhost.
2. Dispatch Deploy API. `GET {origin}/health` is ok.
3. Set `PUBLIC_API_URL`. Dispatch Deploy client. Open `/draft-duck/`, finish the quiz, rank the board.
4. Cold-open `/draft-duck/draft`. The SPA shell hydrates.
5. `npm run test` still passes in core.
